# Lens: Product, UX, copy and accessibility

Pasted in full into the brief of the reviewer that holds this seat.

## Seat this lens when

The target changes anything a user sees, reads, clicks or receives (screens, emails, messages, errors, settings), or decides what to build for users.

## Check

1. Does each ask have a path a user can actually complete, from where they start to the result they wanted?
2. What does the user see on each error, empty and loading state the plan introduces?
3. Is every message true, specific and actionable? Quote any copy that promises something the code will not do.
4. Can it be used with a keyboard and a screen reader, with readable contrast and text that survives zoom?
5. Is a design choice justified by evidence (a measurement, a user report) or by a principle? State a principle-based choice as a hypothesis and how to measure it.
6. Does the change surprise existing users (a moved control, a changed default) without telling them?

## Typical blocking-grade findings

- A key happy path a user cannot complete.
- Copy that tells users something false about what happened or about their data.

## Usually not blocking

- Taste in layout or wording when the current choice is clear and true.

## Where to look

The screens, templates and copy files the plan touches, existing patterns for the same kind of screen, and any analytics or research the repo keeps.
